# コンセプトドキュメント

## コンセプト
AIと人間がワイヤーフレームを介してUIを共同設計するためのテキストベースツールチェーン。「AIが出力しやすく、人間が確認・修正しやすい」を両立することを目的とする。

## 設計思想
アスキーアートは手軽だがAIが正確に生成しにくい。ビジュアルツールは正確だがAIと相性が悪い。その中間として構造を記述するDSLをコアに置き、アスキーアートは確認用の出力として位置づける。
DSL（構造）← コア
  ↓ render
アスキーアート（確認用）← コードブロック内で表示

## 仕組み
レイヤー構成
AIエージェント
  ↓ 独自DSLを出力
DSLパーサー
  ↓ レンダリング
アスキーアート（コードブロック）
  ↓ 人間が確認・修正
VSCode拡張（GUIエディタ）
  ↓ DSLに書き戻し
AIエージェントに渡す

## DSLフォーマット（v2: 独自DSL）

`@` プレフィックス + インデント階層による独自DSL。Markdown見出しのセマンティクス衝突を回避し、ツールなしでも構造が分かる。

```
# コメント行
@layout stack
  @component header
    [ Logo ] News Portal [ 設定 ] [ ログアウト ]
  @layout split ratio=30/70
    @branch left
      @component table
        | date | title | status |
        |------|-------|--------|
      @component nav
        [ < ] 1 2 [3] 4 5 [ > ]
    @branch right
      @component panel height=8
        - title
        - meta
        - summary
        [ Open ] [ Mark as read ]
```

### 構文ルール
- `@layout <kind> [key=value...]` — レイアウト（stack, split）
- `@component <kind> [key=value...]` — コンポーネント（header, table, panel, nav, list, footer）
- `@branch <kind>` — ブランチ（left, right, top, bottom）
- `# ...` — 行コメント（インデント階層に影響しない）
- インデントされた非`@`行 — content（`@@`で`@`をエスケープ）
- インデント: スペース2個
- パラメータ: `key=value` のみ（`ratio=50/50`, `height=10`, `width=80`）
- 拡張子: `.wire`

## 出力（アスキーアート）
等幅フォント環境のコードブロック内での表示を前提とする。ASCII記号のみ使用し環境依存を最小化。

## コンポーネント
ツールチェーンは3つの要素で構成される。

### DSLライブラリ（CLIツール）
- DSL→アスキーアートのレンダリング
- アスキーアート→DSLの逆変換（自ライブラリ出力のみ）
- MCPサーバーとして公開可能

### VSCode拡張
- DSLファイルをGUIでビジュアル編集
- マウスでコンポーネントを配置・リサイズ
- 編集結果をDSLに書き戻す

### プロンプトテンプレート
- AIにDSLを出力させるための標準プロンプト
- モデル非依存で動作することを目標とする

## ユースケース
### AI→人間
AIエージェントがUI提案をDSLで出力し、CLIでアスキーアートに変換してチャット上で共有する。レビュアーはコードブロックを見てフィードバックを返す。
### 人間→AI
VSCode拡張でワイヤーフレームをGUI操作で作成し、DSLをコピーしてAIエージェントに渡す。エージェントはDSLを読んでUIコードを生成する。
### エージェント間
MCPサーバー経由でエージェントがDSLを生成・修正しながらUIを反復設計する。人間は要所でVSCode拡張を使って確認・介入する。

## 制約と割り切り
- アスキーアートはコードブロック内表示のみ保証（Slack等での崩れは許容）
- 逆変換は自ライブラリ出力のみ対応（外部アスキーアートのパースは対象外）
- スタイル（色、余白など）は対象外、構造のみ表現する
